## Синтаксис SELECT

Основные части запроса:

1. `SELECT` — какие столбцы или выражения вернуть.
2. `FROM` — откуда брать строки.
3. `JOIN ... ON` — какие таблицы присоединить и по какому условию.
4. `WHERE` — какие отдельные строки оставить.
5. `GROUP BY` — как объединить строки в группы.
6. `HAVING` — какие группы оставить.
7. `ORDER BY` — как отсортировать готовый результат.
8. `LIMIT / OFFSET` — какую часть результата вернуть.

```sql
SELECT DISTINCT columns
FROM table
JOIN other_table ON condition
WHERE row_condition
GROUP BY columns
HAVING group_condition
ORDER BY columns ASC|DESC
LIMIT n OFFSET m;
```

`UPDATE` и `DELETE` без `WHERE` затрагивают все строки таблицы.

## Порядок выполнения SELECT

**Порядок записи:**

`SELECT → FROM/JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT/OFFSET`

**Логический порядок обработки:**

`FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET`

Отсюда главное:

- `WHERE` работает с исходными строками **до группировки**.
- `GROUP BY` формирует группы из оставшихся строк.
- `HAVING` фильтрует уже сформированные группы.
- `SELECT` формирует столбцы результата.
- `ORDER BY` сортирует практически готовый результат.
- `LIMIT/OFFSET` применяются в самом конце.

## Группировка

- `GROUP BY` объединяет строки с одинаковыми значениями указанных столбцов в группы.
- Агрегатная функция вычисляет одно значение по множеству строк группы.
- Основные агрегаты: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.
- `COUNT(*)` считает строки, `COUNT(column)` — только строки, где `column IS NOT NULL`.
- В `SELECT` при группировке обычно находятся столбцы из `GROUP BY` и агрегатные выражения.
- `WHERE` отбрасывает строки **до** группировки, `HAVING` — группы **после** неё.

```sql
SELECT department, COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;
```

## Ограничения и ключи

Ограничения поддерживают целостность данных: СУБД сама запрещает состояние, нарушающее заданные правила.

- `PRIMARY KEY` — однозначно идентифицирует строку; уникален и не `NULL`.
- Первичный ключ может состоять из нескольких столбцов.
- `FOREIGN KEY` — значение должно ссылаться на существующий ключ связанной таблицы.
- `NOT NULL` — значение обязательно должно присутствовать.
- `UNIQUE` — запрещает повторение значения или комбинации значений.
- `CHECK` — значение/строка должны удовлетворять условию.
- Ограничения можно задавать при создании таблицы или позже через `ALTER TABLE`.

Для внешнего ключа при изменении родительской строки можно определить поведение:

- `RESTRICT` — запретить удаление/изменение, пока существуют ссылки.
- `CASCADE` — автоматически распространить удаление/изменение на связанные строки.
- Возможны также стратегии вроде `SET NULL` и `SET DEFAULT`, если это допускает схема.

В PostgreSQL ограничение можно сначала добавить как `NOT VALID`: оно начнёт проверять новые и изменяемые строки, но старые данные сразу полностью не сканируются. Позже старые строки проверяются через `VALIDATE CONSTRAINT`.

```sql
CREATE TABLE products (
    id INT PRIMARY KEY,
    category_id INT REFERENCES categories(id),
    price NUMERIC CHECK (price >= 0)
);
```

## Транзакции

Транзакция — последовательность операций, которая рассматривается БД как единое целое: изменения либо успешно фиксируются вместе, либо транзакция откатывается.

### Что происходит во время транзакции

1. `BEGIN` / `START TRANSACTION` открывает транзакцию.
2. Команды внутри неё выполняются последовательно.
3. Собственные изменения транзакция видит сразу.
4. Другие транзакции обычно не видят эти изменения до `COMMIT`.
5. При изменении строки PostgreSQL защищает её от конфликтующих изменений; конкурентный `UPDATE` той же строки может ждать.
6. Обычные чтения в PostgreSQL работают через **MVCC**: читается подходящая версия строки из снимка данных, поэтому чтение обычно не блокирует запись и наоборот.
7. `COMMIT` делает изменения зафиксированными и видимыми согласно правилам изоляции.
8. `ROLLBACK`, ошибка или незавершённая транзакция при сбое отменяют её изменения.

### ACID

- **Atomicity** — транзакция выполняется целиком или не выполняется вовсе.
- **Consistency** — после транзакции БД должна удовлетворять своим ограничениям и правилам.
- **Isolation** — параллельные транзакции должны быть защищены от недопустимого взаимного влияния.
- **Durability** — после успешного `COMMIT` результат должен пережить сбой системы.

### Аномалии параллельной работы

- **Dirty read** — чтение ещё не зафиксированных изменений другой транзакции.
- **Non-repeatable read** — одинаковый запрос внутри одной транзакции повторно видит изменившуюся строку.
- **Phantom read** — повторный запрос по условию получает другой набор строк из-за вставок/удалений другой транзакции.
- **Lost update** — одно конкурентное изменение фактически затирает другое.

### Уровни изоляции PostgreSQL

| Уровень | Суть |
|---|---|
| `READ UNCOMMITTED` | В PostgreSQL ведёт себя как `READ COMMITTED`; грязное чтение не разрешается |
| `READ COMMITTED` | Каждый оператор получает актуальный снимок зафиксированных данных; уровень по умолчанию |
| `REPEATABLE READ` | Транзакция работает с одним снимком; повторные чтения стабильны, возможен конфликт сериализации |
| `SERIALIZABLE` | Результат должен соответствовать некоторому последовательному выполнению транзакций; конфликтующие транзакции могут потребовать повтора |

Чем сильнее изоляция, тем меньше допустимых аномалий, но тем вероятнее конфликт и необходимость повторить транзакцию.

```sql
BEGIN;
-- несколько связанных операций
COMMIT;      -- сохранить
-- ROLLBACK; -- отменить
```

## Индексы

Индекс — отдельная структура данных, которая хранит значения выбранных столбцов в форме, удобной для быстрого поиска, и позволяет найти соответствующие строки таблицы без полного просмотра всех строк.

### Как работает индекс

Без подходящего индекса СУБД часто вынуждена выполнить **sequential scan**: пройти таблицу и проверить строки одну за другой — порядка `O(n)` проверок.

Для обычного индекса PostgreSQL основной структурой является **B-tree**:

- данные индекса организованы как сбалансированное дерево;
- внутренние узлы направляют поиск в нужную часть дерева;
- в листьях находятся отсортированные ключи и ссылки на строки/версии строк таблицы;
- высота дерева небольшая, поэтому поиск конкретного диапазона начинается примерно за `O(log n)`;
- после нахождения ключей СУБД получает нужные строки таблицы, если данные нельзя полностью взять из индекса.

B-tree хранит ключи упорядоченно, поэтому полезен не только для `=`, но и для сравнений `<`, `>`, диапазонов и подходящего `ORDER BY`.

### Когда индекс особенно полезен

- Частый поиск по столбцу в `WHERE`.
- Соединения по столбцам из `JOIN ... ON`.
- Выбор небольшого числа строк из большой таблицы.
- Диапазонный поиск.
- Сортировка, совпадающая с порядком индекса.
- Часто используемые ключи связей.

Индекс не гарантирует ускорение: оптимизатор PostgreSQL сам оценивает стоимость и может выбрать полный просмотр таблицы, например если таблица маленькая или запрос всё равно возвращает большую её часть.

### Составной индекс

Индекс `(a, b)` сначала упорядочен по `a`, а внутри одинаковых `a` — по `b`.

Поэтому порядок столбцов важен. Такой индекс естественно подходит для условий по `a` и по комбинации `a, b`; условие только по `b` обычно использует его значительно хуже.

### Цена индекса

Индекс ускоряет чтение ценой дополнительных ресурсов:

- занимает место на диске;
- при `INSERT` нужно добавить новый ключ в индексы;
- при `DELETE` и `UPDATE` индексные структуры тоже требуют обслуживания;
- слишком большое число индексов замедляет изменение данных.

Поэтому индекс стоит создавать не «на каждый столбец», а под реальные запросы.

### Индексы и ограничения

- PostgreSQL создаёт индекс для `PRIMARY KEY`.
- PostgreSQL создаёт индекс для `UNIQUE`.
- Для `FOREIGN KEY` индекс на ссылающемся столбце автоматически не создаётся; его часто имеет смысл добавить вручную.

```sql
CREATE INDEX person_name_idx ON person(last_name, first_name);
```

## Последовательности и IDENTITY

Последовательность — объект БД, выдающий новые числовые значения. Она удобна для генерации идентификаторов и не требует вручную искать текущий максимальный `id`.

- `nextval` — получить следующее значение и продвинуть последовательность.
- `currval` — последнее полученное значение последовательности в текущей сессии.
- `setval` — установить её текущее состояние.
- `START WITH` — начальное значение.
- `INCREMENT BY` — шаг.
- `CACHE` — заранее резервируемый набор значений для уменьшения накладных расходов.
- `IDENTITY` связывает автоматическую генерацию идентификатора со столбцом таблицы.
- `SERIAL` — более старый PostgreSQL-подход поверх последовательности; для новых схем обычно предпочтительнее `IDENTITY`.

```sql
id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

## Подзапросы, CTE и представления

### Подзапрос

Подзапрос — запрос, результат которого используется другим запросом. Он может вернуть одно значение, одну строку или набор строк — допустимая форма зависит от места использования.

### CTE (`WITH`)

CTE даёт промежуточному результату имя на время одного SQL-оператора. Это удобно для разбиения сложного запроса на понятные части и дальнейшего обращения к результату как к временной таблице внутри этого оператора.

### VIEW

Представление — сохранённый запрос с именем. Обычный `VIEW` хранит определение запроса, а не отдельную копию его результата; при обращении СУБД использует запрос представления.

```sql
WITH active_users AS (
    SELECT id FROM users WHERE active = TRUE
)
SELECT * FROM active_users;
```

## Операции над результатами

Операции `UNION`, `INTERSECT`, `EXCEPT` работают не с таблицами напрямую, а с результатами запросов. Соединяемые запросы должны возвращать одинаковое число столбцов с совместимыми типами.

- `UNION` — строки обоих результатов; дубликаты удаляются.
- `UNION ALL` — строки обоих результатов; дубликаты сохраняются, поэтому не требуется их удалять.
- `INTERSECT` — строки, присутствующие в обоих результатах.
- `EXCEPT` — строки первого результата, которых нет во втором.

# Примеры ключевых слов

Короткие примеры для быстрого восстановления синтаксиса. В каждом блоке главное ключевое слово выделено в типичном контексте.

### SELECT

```sql
SELECT name, price
FROM products;
```

Возвращает указанные столбцы или вычисленные выражения из результата запроса.

### FROM

```sql
SELECT *
FROM products;
```

Указывает таблицу или другой источник, из которого берутся строки.

### WHERE

```sql
SELECT * FROM products
WHERE price > 1000;
```

Оставляет только строки, для которых указанное условие истинно.

### DISTINCT

```sql
SELECT DISTINCT category_id
FROM products;
```

Убирает повторяющиеся строки из результата `SELECT`.

### ORDER BY

```sql
SELECT * FROM products
ORDER BY price DESC;
```

Сортирует строки по указанным столбцам: `ASC` — по возрастанию, `DESC` — по убыванию.

### LIMIT

```sql
SELECT * FROM products
LIMIT 10;
```

Оставляет в результате не более указанного количества строк.

### OFFSET

```sql
SELECT * FROM products
LIMIT 10 OFFSET 20;
```

Пропускает указанное количество первых строк результата.

### AS

```sql
SELECT AVG(price) AS avg_price
FROM products;
```

Задаёт временное имя столбцу, выражению или таблице внутри запроса.

### INSERT INTO

```sql
INSERT INTO products (name, price)
VALUES ('Book', 500);
```

Добавляет в таблицу новую строку или набор строк с указанными значениями.

### UPDATE

```sql
UPDATE products
SET price = 600
WHERE id = 1;
```

Изменяет указанные столбцы строк, подходящих под `WHERE`; без `WHERE` — всех строк.

### DELETE FROM

```sql
DELETE FROM products
WHERE id = 1;
```

Удаляет строки, подходящие под `WHERE`; без `WHERE` — все строки таблицы.

### CREATE TABLE

```sql
CREATE TABLE users (
    id INT PRIMARY KEY,
    name TEXT
);
```

Создаёт пустую таблицу с указанными столбцами, типами и ограничениями.

### ALTER TABLE

```sql
ALTER TABLE users
ADD COLUMN email TEXT;
```

Изменяет структуру существующей таблицы: столбцы, ограничения и другие свойства.

### DROP TABLE

```sql
DROP TABLE users;
```

Удаляет таблицу вместе с хранящимися в ней данными.

### GROUP BY

```sql
SELECT category_id, COUNT(*)
FROM products
GROUP BY category_id;
```

Объединяет строки с одинаковыми значениями указанных столбцов в группы для агрегатов.

### HAVING

```sql
SELECT category_id, COUNT(*)
FROM products
GROUP BY category_id
HAVING COUNT(*) > 5;
```

Оставляет после `GROUP BY` только группы, для которых условие истинно.

### Агрегатные функции

```sql
SELECT COUNT(*), SUM(price), AVG(price), MIN(price), MAX(price)
FROM products;
```

Считают одно итоговое значение по набору строк или отдельно по каждой группе.

### JOIN / INNER JOIN

```sql
SELECT *
FROM products
JOIN categories ON products.category_id = categories.id;
```

Соединяет строки двух таблиц и оставляет только пары, совпавшие по условию `ON`.

### LEFT JOIN

```sql
SELECT *
FROM products
LEFT JOIN categories ON products.category_id = categories.id;
```

Оставляет все строки левой таблицы, добавляя совпадения справа или `NULL`, если совпадения нет.

### RIGHT JOIN

```sql
SELECT *
FROM products
RIGHT JOIN categories ON products.category_id = categories.id;
```

Оставляет все строки правой таблицы, добавляя совпадения слева или `NULL`, если совпадения нет.

### FULL JOIN

```sql
SELECT *
FROM products
FULL JOIN categories ON products.category_id = categories.id;
```

Оставляет все строки обеих таблиц: совпавшие соединяет, для несовпавших подставляет `NULL`.

### CROSS JOIN

```sql
SELECT *
FROM colors
CROSS JOIN sizes;
```

Соединяет каждую строку первой таблицы с каждой строкой второй — декартово произведение `N × M`.

### ON

```sql
SELECT *
FROM orders
JOIN users ON orders.user_id = users.id;
```

Задаёт условие, по которому `JOIN` сопоставляет строки двух таблиц.

### UNION

```sql
SELECT email FROM customers
UNION
SELECT email FROM suppliers;
```

Объединяет строки двух совместимых запросов и удаляет дубликаты.

### UNION ALL

```sql
SELECT email FROM customers
UNION ALL
SELECT email FROM suppliers;
```

Объединяет строки двух совместимых запросов, сохраняя дубликаты.

### INTERSECT

```sql
SELECT email FROM customers
INTERSECT
SELECT email FROM subscribers;
```

Оставляет строки, которые присутствуют в результатах обоих запросов.

### EXCEPT

```sql
SELECT email FROM customers
EXCEPT
SELECT email FROM blocked;
```

Оставляет строки первого запроса, которых нет в результате второго.

### WITH

```sql
WITH expensive AS (
    SELECT * FROM products WHERE price > 10000
)
SELECT * FROM expensive;
```

Создаёт именованный промежуточный результат, который можно использовать дальше внутри одного запроса.

### CREATE VIEW

```sql
CREATE VIEW expensive_products AS
SELECT * FROM products WHERE price > 10000;
```

Сохраняет запрос как представление, к которому затем можно обращаться подобно таблице.

### CASE

```sql
SELECT price,
       CASE WHEN price > 10000 THEN 'expensive' ELSE 'cheap' END AS kind
FROM products;
```

Возвращает значение в зависимости от первого выполненного условия.

### PRIMARY KEY

```sql
CREATE TABLE users (
    id INT PRIMARY KEY
);
```

Задаёт уникальный непустой ключ, однозначно идентифицирующий каждую строку.

### FOREIGN KEY / REFERENCES

```sql
CREATE TABLE orders (
    user_id INT REFERENCES users(id)
);
```

Требует, чтобы значение ссылалось на существующий ключ другой таблицы.

### NOT NULL

```sql
CREATE TABLE users (
    name TEXT NOT NULL
);
```

Запрещает хранить `NULL` в указанном столбце.

### UNIQUE

```sql
CREATE TABLE users (
    email TEXT UNIQUE
);
```

Запрещает повторение указанного значения или комбинации значений.

### CHECK

```sql
CREATE TABLE products (
    price NUMERIC CHECK (price >= 0)
);
```

Разрешает запись строки только если заданное условие выполняется.

### CREATE INDEX

```sql
CREATE INDEX products_price_idx
ON products(price);
```

Создаёт индекс по указанным столбцам, чтобы ускорять подходящие поиски, соединения и сортировки.

### DROP INDEX

```sql
DROP INDEX products_price_idx;
```

Удаляет указанный индекс, не удаляя данные самой таблицы.

### BEGIN / START TRANSACTION

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
```

Начинает транзакцию: последующие изменения ждут фиксации `COMMIT` или отмены `ROLLBACK`.

### COMMIT

```sql
BEGIN;
UPDATE accounts SET balance = 1000 WHERE id = 1;
COMMIT;
```

Фиксирует все изменения текущей транзакции и завершает её.

### ROLLBACK

```sql
BEGIN;
UPDATE accounts SET balance = 0 WHERE id = 1;
ROLLBACK;
```

Отменяет все изменения текущей транзакции и завершает её.
